# Chat UI v3 — рендеринг Markdown в ответах (2026-09-07)

## Контекст

После Chat v2 (см. `CHAT-UI-V2.md`) ручная проверка на сервере .22
выявила: ответы модели показываются как обычный текст. Пример из
проверки:

```
# Заголовок
**жирный текст**
*курсив*
- список
> цитата
`inline code`
```python
def hello():
    print("Hello")
```

Chat v2 сознательно выводил только экранированный текст (`esc()`) —
Markdown-рендеринг был зафиксирован как ограничение и бэклог v3.
Здесь он закрыт.

## Решение

**marked + DOMPurify, вендоренные локально** (как Chart.js в v1):

- `webui/static/js/vendor/marked.min.js` — marked v12.0.2 (MIT),
  с CDN jsdelivr, парсер Markdown с GFM (таблицы, зачёркивание,
  task-lists).
- `webui/static/js/vendor/purify.min.js` — DOMPurify v3.1.6
  (Apache-2.0 / MPL-2.0), sanitizer для HTML-вывода.
- `webui/static/js/md.js` — мост `renderMarkdown(text)`:
  `marked.parse()` → `DOMPurify.sanitize()` → HTML.

Почему не свой парсер: marked 12 — зрелый парсер с GFM, свой
«достаточный» парсер — это бесконечные edge-cases (вложенные списки,
escaped-символы, autolink), а безопасность всё равно требует
DOMPurify поверх любого рендера. Два вендоренных файла (~57 KB
суммарно) не тянут никакого runtime-билла.

## Безопасность (обязательная часть Markdown в чате)

marked **не** санитизирует HTML внутри Markdown — это документированное
поведение. Модель может вернуть (или злоумышленник через промпт
внедрить) `<script>`, `<img onerror=...>`, `[x](javascript:...)`.
Поэтому санитизация DOMPurify — не опция, а обязательный шаг цепочки:

- `<script>` и содержимое — удаляются;
- обработчики (`onerror=` и прочие `on*`) — удаляются;
- `javascript:`-URL в ссылках — удаляются (текст ссылки остаётся);
- `iframe/object/embed/form/input/button/style` и атрибут `style`
  — запрещены явно (FORBID_TAGS/FORBID_ATTR);
- безопасное форматирование (заголовки, списки, `pre/code` с классом
  `language-*`, ссылки на https, таблицы, цитаты) — сохраняется.

## Деградация

`md.js` проверяет доступность библиотек (`__markdownAvailable()`).
Если marked или DOMPurify отсутствуют/сломаны — мост возвращает
**экранированный** текст (`esc()`), как в v2. Чат никогда не показывает
несанитизированный HTML и не падает: без библиотек это просто v2.

Проверка `typeof window.DOMPurify` принимает и `object`, и `function`:
в некоторых UMD-окружениях DOMPurify экспортируется функцией-фабрикой
с прицепленными методами.

## Интеграция в стриминг

В `chat.js`:

- узел ответа теперь `bodyNode` (`span.ok.chat-md`) — блочный контейнер
  под Markdown-HTML;
- на каждый delta-чанк: `bodyNode.innerHTML = renderMarkdown(reply)` —
  перерендер накопленного буфера (курсор `▍` переносится в конец);
  перерендер на чанк — осознанный компромисс: стрим маленький, зато
  видимая разметка всегда совпадает с финальной;
- в `finally` — финальный `renderMarkdown(reply)` без курсора
  (нормализует незакрытый синтаксис последнего чанка);
- `index.html`: `vendor/marked.min.js` + `vendor/purify.min.js`
  подключены до `md.js` и до `pages/chat.js` (порядок проверяется
  тестом).

## CSS

Секция «Chat v3 (markdown replies)» в `app.css`: `.chat-md` стилизует
заголовки (h1 с подчёркиванием), списки, цитаты (акцентная левая
полоса), inline-код (жёлтый на тёмном фоне), fenced-блоки (панель
`#04060a` с горизонтальным скроллом), таблицы, ссылки, `<hr>` — всё в
существующей терминальной палитре (var(--border-2), var(--accent) и
т.д.).

## Тесты

- `tests/test_chat_markdown.py` — реальный `md.js` + реальные
  вендоренные marked/DOMPurify внутри jsdom (node):
  - полный сэмпл из ручной проверки (.22) — заголовок/жирный/курсив/
    список/цитата/inline-code/fenced code с `language-python`;
  - GFM: таблицы, `~~зачёркивание~~`;
  - XSS: `<script>` (тег и содержимое), `onerror=`, `javascript:`,
    `iframe/object/form/input` — всё удаляется, безопасное — остаётся;
  - деградация: сломанный marked → экранированный текст; DOMPurify
    отсутствует → экранированный текст;
  - пустой/undefined/null вход → пустая строка;
  - chat.js подключает `renderMarkdown` в delta- и финальный рендер;
  - порядок скриптов в index.html и наличие вендоренных файлов.
  Тест пропускается (skip), если node или jsdom недоступны —
  регрессии на порядок скриптов и статический состав остаются.
- `tests/test_chat_frontend.py` — дополнен: pipe-проверка (answers
  проходят через `renderMarkdown`, один узел `.chat-md`, финальный
  буфер совпадает), частичный ответ при ошибке тоже рендерится.

Полный набор: **145 passed**.

## Ограничения / бэклог

- Подсветка синтаксиса в fenced-блоках не подключена (классы
  `language-*` уже проставляются — highlight.js ложится поверх без
  изменений в chat.js).
- Перерендер на каждый delta-чанк: O(len²) на весь ответ; при очень
  длинных ответах можно перейти на отложенный рендер (раз в N мс).
