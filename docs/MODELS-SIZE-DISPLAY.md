# Models UI — отображение размера моделей (2026-09-07)

## Проблема

Размеры моделей в Models UI не совпадали с `ollama ls`:

| Модель | `ollama ls` | WebOllama (до) |
|---|---|---|
| `ornith-vision:9b` | **6.7 GB** | **6.2 GB** |

## Причина

Единственный байт-форматтер фронтенда — `fmtBytes` в
`webui/static/js/api.js` — делил байты на **1024** (двоичные единицы,
то есть GiB), но подписывал результат как **GB**:

```js
// было
while (n >= 1024 && i < units.length - 1) { n /= 1024; i++; }
```

Ollama CLI (`ollama ls`, `ollama ps`) печатает размеры моделей в
**десятичных GB** — `bytes / 1_000_000_000`. Проверка на примере:

- `6_700_000_000` байт → `6_700_000_000 / 1024³ = 6.2` «GB» (бинарное) —
  это и показывал WebOllama;
- `6_700_000_000 / 10⁹ = 6.7 GB` (десятичное) — это показывает `ollama ls`.

## Решение

`fmtBytes` переведён на десятичные шаги:

```js
// стало
while (n >= 1000 && i < units.length - 1) { n /= 1000; i++; }
```

- единицы: `B, KB, MB, GB, TB, PB` — десятичные (1 kB = 1000 B);
- точность/округление сохранены: по умолчанию 1 знак после запятой для
  KB и выше, 0 — для байт (`toFixed`); явный параметр `dp` работает как
  прежде;
- порог перехода к следующей единице — 1000 (значение `999_999` байт
  показывается как `1000.0 KB`, `999_999_999` — как `1000.0 MB`; такое же
  поведение было и раньше на границе 1024).

## Почему значение теперь совпадает с `ollama ls`

Ollama internally хранит и отдаёт размер модели в **байтах**
(`/api/tags` → `size`); CLI лишь форматирует их десятично. WebOllama
использует те же сырые байты из того же API — расхождение возникало
исключительно в форматировании. После перехода `fmtBytes` на деление на
1000 число на экране идентично числу CLI для тех же байт:

- `6_700_000_000` → `6.7 GB` (совпадает с `ollama ls`);
- `6_657_199_309` → `6.7 GB` (тот же размер после округления CLI);
- `1_073_741_824` (ровно 1 GiB) → `1.1 GB` — осознанно десятично.

## Источник размера

- Models UI: `GET /api/ollama/models` → OllamaClient → `/api/tags` →
  поле `size` (байты, verbatim);
- Running UI: `GET /api/ollama/running` → `/api/ps` → `size` / `size_vram`;
- **API-значения не изменялись** — правка только в слое отображения.

## Область действия formatter'а

`fmtBytes` — общий форматтер (загружается из `/js/api.js` раньше всех
страниц). Десятичный контракт автоматически применён ко всем местам:

- **Models** — колонка Size (исходная задача);
- **Running** — model VRAM, total;
- **Dashboard / GPU** — GPU VRAM строка, Model VRAM (Ollama);
- **PROCESSOR-блок** — VRAM `used/total`;
- **System/Jobs** — `fmtSpeed` (те же единицы + `/s`), RAM/disk значения.

Проверено: других делений на 1024 в отрисовке размеров моделей нет
(`dashboard.js` делит на 1024³ только для **осей графиков истории** в
GiB — это подписи тиков Chart.js, а не отображаемые размеры моделей, и
на сопоставимость с `ollama ls` не влияет; оси не подписаны «GB» в
таблицах).

## Тесты

`tests/test_size_display.py` (node, реальный `webui/static/js/api.js`):

1. **регрессия задачи**: `6_700_000_000` → `6.7 GB` (не `6.2`),
   `6_657_199_309` → `6.7 GB`;
2. **5.2 GB**: `5_200_000_000` → `5.2 GB`;
3. **MB**: `1_500_000` → `1.5 MB`, `12_345_678` → `12.3 MB`, граница
   `999_999` → `1000.0 KB`;
4. **большие размеры**: `2_000_000_000_000` → `2.0 TB`,
   `1_234_567_890_123` → `1.2 TB`, `15_400_000_000` → `15.4 GB`;
5. **округление**: `6_749_999_999` → `6.7`, `6_800_000_000` → `6.8`,
   `dp=0`/`dp=2` работают как раньше, `1_073_741_824` (1 GiB) → `1.1 GB`
   десятично;
6. edge cases: `null/undefined/NaN` → `—`, `0` → `0 B`, строковые числа;
7. `fmtSpeed` наследует тот же десятичный контракт;
8. source-pin: в `api.js` нет бинарных шагов (`n /= 1024`), `api.js`
   грузится раньше `models/running/dashboard.js`;
9. в `models.js`/`running.js` нет собственного деления на 1024³ —
   размеры идут только через общий форматтер.

## Ограничения

- Десятичные KB/MB/GB technically являются kB/MB/GB (SI), подпись
  остаётся `KB/MB/GB` — как в `ollama ls`; смена подписей на «GiB» не
  требуется, поскольку сравнение идёт именно с CLI.
- Оси истории-графиков (Chart.js тики) строятся в GiB без подписи
  единиц в таблицах; приведение их к decimal не входит в задачу и на
  отображение размеров моделей не влияет.
- Граничные значения (999_999 B → «1000.0 KB») отображаются без
  перехода к следующей единице — поведение идентично прежней логике на
  старой границе 1024.
