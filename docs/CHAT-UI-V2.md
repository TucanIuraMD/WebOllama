# Chat UI v2 — стриминговый чат (2026-09-06)

## Контекст

Страница Chat (`#chat`) была минимальной: `POST /api/chat/run` с
`stream=False`, ответ приходил целиком одной вставкой через
`innerHTML +=`, Enter отправлял однострочный инпут, ошибки и метрики
сводились к одной статусной строке.

Chat v2 превращает страницу в полноценный стриминговый чат: токены
появляются по мере генерации, есть кнопка Stop, история диалога
хранится в состоянии страницы, ошибки отображаются в транскрипте.

## Что сделано

### Backend

1. **`OllamaClient.chat_stream()`** (`webui/ollama_client.py`) —
   async-генератор поверх `POST /api/chat` со `stream: true`.
   Ollama отдаёт NDJSON (по JSON-объекту на строку): промежуточные
   строки содержат куски `message.content`, финальная — `done: true`
   плюс счётчики (`total_duration`, `prompt_eval_count`, `eval_count`).
   Поддержан `cancel_event` (проверяется перед каждой строкой) и
   маппинг ошибок: ConnectError → `OllamaError("Ollama is offline",
   offline=True)`, HTTPError → 502, HTTP ≥400 → код ответа + тело.

2. **`POST /api/chat/stream`** (`webui/routers/chat.py`) — SSE-прокси
   (`text/event-stream`, `StreamingResponse`). Формат событий:
   - `event: delta` — `{"content": "..."}` — инкрементальный текст;
   - `event: done` — `{"model", "total_duration", "prompt_eval_count",
     "eval_count"}` — конец генерации;
   - `event: error` — `{"error": "..."}` — ошибка стрима (включая
     404 «model not found»).
   SSE выбран вместо «сырого» NDJSON-проксирования: на клиенте парсинг
   тривиален (fetch + ReadableStream), зависимости не нужны.
   Валидация payload вынесена в `_validate_payload()` (общая с `/run`):
   model обязателен, `messages` — непустой список объектов со строковым
   `content`, `options` — опциональный объект (temperature и т.п.).
   Аудит пишется по завершении (успех/ошибка/обрыв клиента).

3. **`/api/chat/run` сохранён** для совместимости — блокирующий
   одношаговый ответ без изменений.

4. **Mock** (`webui/mock/__init__.py`) — ветка `/api/chat` при
   `"stream": true` возвращает NDJSON-стрим: 3 куска контента +
   финальная строка с метриками. Real Ollama совместим по формату.

### Frontend (`webui/static/js/pages/chat.js` — переписан)

1. **Стриминг**: `fetch('/api/chat/stream')` + ручной SSE-парсер
   (буферизация по `\n\n`, `event:`/`data:` строки). Ответ пишется в
   отдельный DOM-узел ассистента (span `.ok`) — без пересборки всего
   вывода, без потери прокрутки.

2. **Курсор генерации**: `▍` (класс `.chat-cursor`, CSS-анимация
   мигания) переезжает в конец стрима; по завершении удаляется.

3. **Кнопка Send ↔ Stop**: пока идёт генерация, кнопка становится
   Stop и вызывает `aborter.abort()` (AbortController). Инпут и
   выбор модели на это время заблокированы. После прерывания частичный
   ответ сохраняется в историю (`⏹ stopped`).

4. **История диалога**: массив `messages` (user/assistant) отправляется
   целиком с каждым запросом — модель видит контекст. При ошибке стрима
   частичный ответ сохраняется; если ответа не было вообще, последнее
   user-сообщение откатывается, чтобы не отравлять контекст.

5. **Ошибки в транскрипте**: HTTP-ошибки (401/400/…) и SSE-события
   `error` рендерятся строкой `.err` в выводе + статус. Валидация:
   пустой ввод не отправляется, без выбранной модели — тоже.

6. **Метрики**: после `done` — модель, число сгенерированных токенов
   (`eval_count`), длительность (`fmtDuration(total_duration / 1e9)`).

7. **Clear** — очистка истории (заблокирована во время генерации;
   для выхода из неё есть Stop).

8. **Рендер моделей**: селектор заполняется из `/api/ollama/models`;
   если список пуст (Ollama offline / ошибка загрузки) — страница всё
   равно рендерится с пустым селектом и подсказкой, а не падает.

### CSS (`webui/static/css/app.css`)

- `.chat-cursor` — мигающий курсор генерации (keyframes `chat-blink`).

## Тесты

- `tests/test_chat_stream.py` — бэкенд: NDJSON-стрим клиента
  (куски + финальные метрики), 404 по неизвестной модели, cancel_event,
  полный SSE-флоу через TestClient (`delta…done`), 401 без авторизации,
  400 на валидации, 404-модель как SSE `error`, совместимость `/run`.
- `tests/test_chat_frontend.py` — фронтенд (headless node, без
  браузера): рендер селектора моделей, POST на `/api/chat/stream` с
  CSRF-заголовком, инкрементальные дельты, курсор удаляется после
  завершения, метрики в статусе, Send ↔ Stop переключение, abort,
  SSE-ошибка и HTTP-ошибка в транскрипте, Clear.

## Ограничения

- Markdown/подсветка кода в ответах пока не рендерятся (текст как есть,
  экранировано `esc()`); заложено в бэклог Chat v3.
- Одновременно идёт одна генерация на страницу (Send заблокирован
  до завершения/Stop).
